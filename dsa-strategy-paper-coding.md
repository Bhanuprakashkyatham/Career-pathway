## 📝 PAPER CODING MASTERY STRATEGY

### Why Paper Coding?
Many companies (especially service: TCS, Wipro, Infosys) ask you to write code on paper without running it.

### The Challenge:
- ❌ No IDE autocomplete
- ❌ No syntax highlighting
- ❌ No compiler to catch errors
- ❌ Can't run and test
- ✅ Must write perfect code first time!

---

## 🎯 PAPER CODING PRACTICE METHOD

### Phase 1: Weeks 1-3 (Build Foundation)
**Method:** Solve on LeetCode normally

1. Solve problem on LeetCode
2. Get it accepted
3. Understand the solution completely
4. Write down the approach in plain English

---

### Phase 2: Weeks 4-5 (Transition to Paper)
**Method:** Think → Write → Verify

1. **Think:** Solve problem mentally (5 min)
2. **Write:** Write code on paper/notepad (10 min)
3. **Type:** Type the EXACT code into LeetCode (5 min)
4. **Debug:** If errors, note them and rewrite on paper
5. **Repeat:** Rewrite the same problem until error-free

**Practice:** 3 problems/week this way

---

### Phase 3: Weeks 6-8 (Master Paper Coding)
**Method:** Pure paper coding

1. Print or write problem statement
2. Write code on blank paper
3. Self-review (check syntax, logic, edge cases)
4. Type into LeetCode (NO CHANGES!)
5. If errors, analyze what you missed
6. Rewrite entirely on paper

**Practice:** 5 problems/week this way

## ✍️ PAPER CODING BEST PRACTICES

### 1. Write Clean Code Structure
```
class Solution {
    public int[] twoSum(int[] nums, int target) {
        // Step 1: Create HashMap
        Map<Integer, Integer> map = new HashMap<>();

        // Step 2: Iterate through array
        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            // Step 3: Check if complement exists
            if (map.containsKey(complement)) {
                return new int[] {map.get(complement), i};
            }

            // Step 4: Add to map
            map.put(nums[i], i);
        }

        // Step 5: No solution found
        return new int[] {-1, -1};
    }
}
```

## 🎯 COMMON PAPER CODING MISTAKES (Avoid These!)

### Syntax Errors:
❌ `HashMap map = new HashMap()` → ✅ `Map<Integer, Integer> map = new HashMap<>()`
❌ `for i in range(n):` → ✅ `for (int i = 0; i < n; i++)`
❌ `arr.length()` → ✅ `arr.length` (no parentheses!)
❌ `String s = "hello"; s[0]` → ✅ `s.charAt(0)`

### Logic Errors:
❌ `for (int i = 0; i <= arr.length; i++)` → ✅ `i < arr.length` (avoid out of bounds)
❌ Not handling empty array/null
❌ Forgetting to return value
❌ Wrong loop condition

### Style Errors:
❌ Inconsistent naming (camelCase vs snake_case)
❌ No comments
❌ Messy indentation
❌ Unclear variable names (a, b, x, y)

## 🎯 INTERVIEW DAY PAPER CODING STRATEGY

### When Interviewer Asks: "Write code on paper for X problem"

**Step 1: Clarify (2 min)**
- Ask about input format
- Ask about edge cases
- Confirm expected output
- Ask if you can use standard library (HashMap, etc.)

**Step 2: Explain Approach (3 min)**
- Verbally explain your approach
- Mention time & space complexity
- Get interviewer's approval

**Step 3: Write Code (10-15 min)**
- Follow the template above
- Write slowly and clearly
- Think before writing each line
- Add comments

**Step 4: Dry Run (3 min)**
- Run through code with test case
- Point out each step verbally
- Show it produces correct output

**Step 5: Handle Questions**
- If interviewer points out error, acknowledge and fix
- If stuck, ask for hint
- Stay calm!

## 🎯 TIME COMPLEXITY CHEAT SHEET (MUST MEMORIZE!)

| Operation | Best Case | Average | Worst Case |
|-----------|-----------|---------|-----------|
| **Array access** | O(1) | O(1) | O(1) |
| **Array search** | O(1) | O(n) | O(n) |
| **ArrayList add** | O(1) | O(1) | O(n) |
| **HashMap get/put** | O(1) | O(1) | O(n) |
| **HashSet add/contains** | O(1) | O(1) | O(n) |
| **TreeMap get/put** | O(log n) | O(log n) | O(log n) |
| **LinkedList add** | O(1) | O(1) | O(1) |
| **LinkedList get** | O(1) | O(n) | O(n) |
| **Binary Search** | O(1) | O(log n) | O(log n) |
| **Bubble Sort** | O(n) | O(n²) | O(n²) |
| **Merge Sort** | O(n log n) | O(n log n) | O(n log n) |
| **Quick Sort** | O(n log n) | O(n log n) | O(n²) |

**Memorize This:** O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
